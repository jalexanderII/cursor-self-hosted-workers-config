# Security policy

Do not open a public issue containing credentials, customer identifiers,
internal hostnames, repository contents, or vulnerability details.

Report suspected vulnerabilities privately to the repository owner through the
hosting platform's private vulnerability-reporting feature. Include:

- affected path and commit
- deployment mode and relevant configuration
- reproduction steps
- impact and proposed mitigation

Never submit real Cursor keys, SCM tokens, kubeconfigs, Terraform state, `.env`
files, private keys, or customer configuration.

This reference is maintained on a best-effort basis. Operators are responsible
for reviewing pinned software versions, AWS/Kubernetes support windows, Cursor
documentation, and their own compliance requirements before deployment.
